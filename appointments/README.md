# אפליקציית זימון תורים + תשלומים

אפליקציה לזימון תורים ללקוחות של ליאת, כולל גביית תשלום וקבלה/חשבונית אוטומטית דרך קארדקום.
בשונה מהגרסה הראשונה (סטטית לגמרי), האפליקציה הזו כוללת שרת PHP קטן + מסד נתונים MySQL,
כי תשלום אמיתי וזימון תורים משותף לכולם דורשים מקום מרכזי לשמור בו נתונים בבטחה.

## מה צריך כדי להעלות את זה לאוויר

1. **אחסון עם PHP 8+ ו-MySQL/MariaDB** — כל אחסון בסיסי עם cPanel (או דומה) מתאים.
   זהו אתר PHP רגיל, בלי Node.js ובלי שלב build.
2. **חשבון סליקה בקארדקום** (Cardcom) — כולל מסוף (Terminal), שם API וסיסמת API.
   ניתן להתחיל עם מסוף ההדגמה של קארדקום (מספר 1000) לבדיקות לפני שעוברים לחשבון אמיתי.

## התקנה (פעם אחת)

1. להעלות את כל תיקיית `appointments/` לאחסון (לדוגמה, כך שהיא תשב תחת הדומיין
   כמו `https://your-domain.co.il/appointments/`).
2. ליצור מסד נתונים MySQL ריק (בפאנל האחסון), ולייבא אליו את `api/schema.sql`
   (למשל דרך phpMyAdmin: Import → לבחור את הקובץ → Go).
3. להעתיק את `api/config.sample.php` לקובץ בשם `api/config.php`, ולמלא בו:
   - פרטי החיבור למסד הנתונים (host/name/user/pass) — מתקבלים מחברת האחסון.
   - פרטי חשבון קארדקום (terminal_number / api_name / api_password).
   - `site_base_url` — הכתובת המלאה של תיקיית `appointments` באתר החי.
4. להיכנס לכתובת `api/setup.php` וליצור שם משתמש וסיסמה לאזור הניהול (פעולה חד-פעמית).
5. **בפאנל הניהול של קארדקום**, להגדיר את כתובת ה-Webhook לתשלומים לכתובת:
   `https://your-domain.co.il/appointments/api/payments_callback.php`
6. להיכנס ל-`admin.html`, להתחבר, ולהגדיר בלשונית "הגדרות עסק" את שם העסק,
   מספר הוואטסאפ, שעות הפעילות והשירותים.

## איך זה עובד עכשיו

- **דף ההזמנה** (`index.html`) מציג זמינות אמיתית מהשרת (כולל תורים שכבר נקבעו),
  לא רק לפי שעות פעילות — כך שלא יכולה להיווצר כפילות תורים.
- לקוח/ה ששולח/ת בקשה נכנס/ת למערכת כ"ממתין לאישור", וגם נשלחת הודעת וואטסאפ לליאת (אם הוגדר מספר).
- **אזור הניהול** (`admin.html`, מוגן בהתחברות אמיתית) מציג את כל התורים, מאפשר
  אישור/ביטול/מחיקה, הוספת תורים ידנית (טלפוניים), ועריכת הגדרות העסק והשירותים.
- **גביית תשלום**: מהרשימה, כפתור "גביית תשלום" פותח עמוד תשלום מאובטח בקארדקום
  (הלקוח/ה לא מזין/ה כרטיס אשראי באתר שלנו בכלל — קארדקום מטפלת בכך). לאחר תשלום מוצלח,
  קארדקום שולחת אישור ישירות לשרת שלנו (Webhook) ומפיקה קבלה/חשבונית אוטומטית,
  שמספרה נשמר בתור. **הסטטוס מתעדכן רק לפי אישור מהשרת של קארדקום, לא לפי מה שהדפדפן מדווח** —
  כך שאי אפשר "לזייף" תשלום מוצלח.

## הערה חשובה לגבי שילוב קארדקום

שדות ה-API המדויקים בקובץ `api/CardcomGateway.php` מבוססים על התיעוד הידוע של
Cardcom LowProfile v11, אך **לא אומתו מול התיעוד הרשמי המעודכן** בזמן הכתיבה (לא הייתה
גישה לאתר התיעוד). לפני שמפעילים גבייה מול לקוחות אמיתיים:

1. לבצע עסקת בדיקה מלאה במסוף ההדגמה (1000) ולוודא שהתשלום, ה-Webhook, וההפקה
   האוטומטית של הקבלה עובדים כמצופה.
2. אם משהו לא תואם, לבדוק מול תמיכת קארדקום או התיעוד העדכני שלהם, ולעדכן את
   השדות בקובץ `CardcomGateway.php` בלבד — כל שאר המערכת לא תלויה בפרטים האלה.

## אבטחה

- הסיסמה לאזור הניהול מוצפנת (hash) במסד הנתונים, וההתחברות מוגנת בסשן שרת אמיתי —
  לא עוד קוד PIN גלוי כמו בגרסה הקודמת.
- פרטי מסד הנתונים וחשבון הסליקה נמצאים רק ב-`api/config.php`, שאינו מועלה ל-git
  (ראו `.gitignore`) ואינו נגיש מהדפדפן.
- כרטיסי אשראי אינם עוברים דרך השרת שלנו בכלל — כל הסליקה קורית בעמוד המתארח של קארדקום.
